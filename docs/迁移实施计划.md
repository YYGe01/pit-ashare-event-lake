## 1. 改造结论

新的项目边界：

```text
Qlib / 社区 cn_data / Qlib 增量脚本
  -> 结构化基础行情
  -> 复权因子
  -> 交易日历
  -> instruments / 指数成分

quant_data_center
  -> 非结构化与另类数据采集
  -> 文本和事件标准化
  -> 日频 external factor 加工
  -> 对齐并导出给 Qlib
```

当前默认推进顺序：

```text
确认 Qlib provider 可用
  -> crawl-daily 采公告、新闻和后续研报/舆情
  -> build-factors 构建外部日频因子
  -> sync-parquet
  -> quality
  -> external factor 导出 / Qlib handler 读取
  -> console 观察
```

不再默认推进：

```text
全 A 日线每日采集
全 A 复权因子每日采集
全 A 涨跌停每日采集
历史行情回补底座补齐
回补队列消费
回补控制台展示
```

既有 `plan-backfill` / `run-backfill` / `daily-pipeline` 保留为历史能力、smoke、缺口诊断和应急补数；除非用户明确要求，不主动运行或扩展。

## 5. 时间和 PIT 口径

文本类数据必须保留：

```text
publish_time       来源显示发布时间
publish_date       从 publish_time 派生
collect_time       本系统采集入库时间
observed_at        本系统观察到来源的时间
source_id          来源
raw_object_id      原始证据对象
```

原则：

```text
因子归属用 publish_date，不用 collect_time。
无法确认发布日期的记录不进入 silver，只保留 raw 和失败原因。
历史补采必须保留真实 collect_time，不伪装成过去已经看到。
事件因子进入 Qlib 前必须按交易日历对齐。
```

交易日历优先来自 Qlib provider；QDC 内部 `trade_calendar` 只作为兼容和诊断表。

## 6. Qlib 接入

Qlib 不直接读新闻正文，也不读 DuckDB 控制表。目标流程：

```text

  -> 提供基础 Alpha158/Alpha360 所需 OHLCV 和 $factor

QDC silver/gold
  -> external factor Parquet / Qlib bin
  -> QdcAlpha158WithExternal
  -> qrun / DatasetH / 模型实验
```

```powershell

qdc crawl-daily --date 2026-05-13 --source-id cninfo_announcement --page-size 100 --skip-pdf-download
qdc crawl-daily --date 2026-05-13 --source-id eastmoney_roll_news --page-size 100

```

```powershell
qdc daily-pipeline --date 2026-05-11 --symbols "SZ301421,SZ300001" --batch-size 1 --control-only
```
