# 2026-05-11

## quant_data_center 主线重构

- 目标：把仓库收敛为个人量化统一数据中心 `quant_data_center`，服务 Qlib 研究。
- 配置：保留 `config/quant_data_center.yaml` 作为唯一当前运行配置，定义数据根目录、DuckDB 路径、Parquet/QLib/logs 目录和迁移阶段策略。
- 代码：保留 `src/quant_data_center/` 包和 `qdc` CLI，当前支持 `validate-config`、`init`、`db-info`、`smoke`、`console`、`plan-backfill`、`list-backfill`、`run-backfill`、`refresh-universe`、`list-universe`、`daily`、`build-factors`、`sync-parquet`、`quality`、`export-qlib`、`verify-qlib`。
- 存储：新增 DuckDB 控制 schema `qdc_meta`，包含 `job_run`、`backfill_task`、`dataset_watermark`、`source_object`、`quality_issue`。
- Silver：新增 `qdc_silver.stock_basic`、`universe_constituent`、`trade_calendar`、`daily_bar`、`adj_factor`、`price_limit`、`trade_status`、`announcement`、`news`、`daily_news_factor`、`daily_announcement_factor`，并由 `SilverStore` 统一 upsert。
- 采集：AkShare 回补已支持 `stock_basic`、`trade_calendar`、`daily_bar`、`adj_factor`、`price_limit`、`trade_status`、`announcement`、`news`。
- 对象层：阶段 2 回补已写入 raw JSON、bronze Parquet，并在 `qdc_meta.source_object` 登记 content hash、文件大小和路径。
- Universe：`refresh-universe` 可写入 AkShare 指数成分快照；`plan-backfill` 优先使用最新快照，缺失时再回退到配置静态样例。
- Daily：`qdc daily` 可按日期和 universe 编排交易日历、行情、复权、涨跌停、交易状态、公告和新闻任务，并支持 `--control-only` 验证状态流。
- Retry：`qdc run-backfill --retry-failed` 可显式重试 `failed` 任务，默认 `run-backfill` 仍只运行 `pending` 任务。
- 因子：`qdc build-factors` 已支持 `news_v1`、`announcement_v1` 和 `all`，生成日频新闻/公告 count 因子。
- Parquet：新增 `QdcParquetSync`，可从 DuckDB silver 派生 silver Parquet 和 `gold/daily_research` Parquet。
- 质量：新增 `QualityChecker` 和 `qdc quality`，检查基础表空值、OHLC 区间、复权因子、涨跌停区间和交易状态枚举，并写入 `qdc_meta.quality_issue`。
- Qlib：新增 `QlibExporter` 和 `qdc export-qlib`，导出 day 频 calendars、instruments 和 features bin 文件，包含行情、vwap、复权、涨跌停和新闻/公告 count 因子；新增 `qdc verify-qlib`，通过本地 Qlib 读取导出的 provider 并输出严格 JSON。
- Console：新增 `qdc console` 本地只读 Web 控制台，直接读取 DuckDB 展示总览、回补任务、silver 数据预览、质量问题和 Qlib 导出索引。
- 清理：当前主线只保留 QDC 代码、配置、测试和文档；历史采集湖实现、配置、测试和长文档已从仓库主线移除。
- 注意：DuckDB 当前按单写进程使用；不要并行执行多个会写同一个 `qdc.duckdb` 的命令。
