# 每日非结构化采集与 Qlib 外部因子实施计划

> 创建日期：2026-05-12
> 重写日期：2026-05-14
> 当前定位：这是 QDC 当前每日采集状态和下一步的唯一入口。结构化基础行情由 Qlib `cn_data` 维护，QDC 默认聚焦公告、新闻、研报、舆情等非结构化数据和 external factors。

## 1. 一句话结论

当前项目主线已经调整为：

```text
Qlib / 社区 cn_data / Qlib 增量脚本
  -> 维护基础行情、复权因子、交易日历和 instruments

QDC
  -> 采集非结构化数据
  -> 归一化为 announcement / news / 后续 research_report / sentiment 等表
  -> 构建 daily external factors
  -> 对齐到 Qlib provider_uri
```

因此，QDC 不再以“全 A 日线、复权、涨跌停每日采集”为默认目标。既有 `daily-pipeline` 和 AkShare 结构化 collector 保留为历史能力、smoke、诊断和应急补数，不再作为 P0 主线。

当前默认入口：

```text
qdc crawl-daily       非结构化文档每日采集
qdc build-factors     文本事件日频因子
qdc sync-parquet      DuckDB 到 Parquet 同步
qdc quality           基础质量检查
qdc console           本地观察面
```

## 4. 当前默认数据源边界

实体映射基准：

```text
公告、新闻、研报和舆情等文档源的股票实体映射以 qdc_silver.stock_basic 为准。
Qlib provider 的 instruments/all.txt 只用于基础行情健康检查和 Qlib 读取验证，不作为文档采集默认股票池。
stock_basic 为空时，标题里即使出现股票简称也无法稳定映射到 instrument，必须先刷新 stock_basic。
```

### 公告

| source_id | 当前定位 | 默认策略 |
| --- | --- | --- |
| `cninfo_announcement` | 公告主源 | 默认采 metadata；PDF 下载按需开启 |
| `sse_announcement` | 上交所公告补源 | 默认可跳过 PDF 下载 |
| SZSE / BSE | 候选 | 确认稳定日期字段后再接入 |

公告硬规则：

```text
必须保留 publish_time / publish_date / collect_time。
publish_date 来自来源披露时间，不用 collect_time 伪造。
PDF 原文保存必须记录 hash、size、object_id 和下载状态。
默认不把 PDF 下载作为每日 P0，先稳定 metadata 和事件因子。
```

### 新闻

| source_id | 当前定位 | 风险 |
| --- | --- | --- |
| `eastmoney_roll_news` | 当日滚动新闻补位 | 适合近实时，不适合历史主源 |
| `sina_finance_news` | 近实时补位 | 隔天历史日期可靠性有限 |
| `nbd_company_news` | 手动 smoke 源 | 本地记录出现 SSL/502 失败，已退出默认每日源 |
| 厂商级 opt-in 源 | 覆盖观察和补位 | 不作为训练级历史新闻结论 |

新闻硬规则：

```text
必须解析明确 YYYY-MM-DD HH:MM[:SS]。
无法确认发布日期的记录不进入 silver。
当前免费新闻源不用于判断新闻 alpha 是否有效。
正式训练需要授权历史新闻源或可长期稳定追溯的公开源。
```

### 非结构化日期扫描算法

非结构化源按日期口径分两类处理，后续新增研报、舆情、互动问答等源也默认套用这个判断框架。

第一类是来源支持精确日期查询的源，例如 `cninfo_announcement` 和 `sse_announcement`：

```text
请求参数必须显式传目标日期 D。
如果来源返回总页数，默认翻完所有页。
只有显式 smoke / 调试时才传 --max-pages。
如果 --max-pages 小于来源总页数，manifest 必须记录 date_scan_complete=false 和 date_scan_stop_reason=max_pages。
silver 只接受来源日期字段等于 D 的记录。
```

第二类是倒序滚动列表源，例如 `eastmoney_roll_news` 和 `sina_finance_news`：

```text
目标日期 D 的时间窗为 [D 00:00:00, D+1 00:00:00)。
从最新页开始逐页扫描。
publish_time >= D+1 的记录判为 newer，只进 raw/bronze，不进 silver。
D <= publish_time < D+1 的记录判为 target，才进入映射、document records、silver 和因子。
publish_time < D 的记录判为 older。
一旦已经命中过 target，并连续看到 2 个整页 older，再停止，防止页面轻微乱序。
如果第一页或扫描过程中已经整页早于 D 且从未命中过 target，认为目标日无可用记录并停止。
默认不传 --max-pages，由 hard_max_pages 防止无限翻页；当前 hard_max_pages=200。
如果打到 --max-pages / hard_max_pages / source_timeout，manifest 必须记录 date_scan_complete=false。
```

滚动源 manifest 必须保留这些排障字段：

```text
date_scan_strategy
target_date / target_start / target_end_exclusive
date_scan_complete
date_scan_stop_reason
date_scan_pages_scanned
scanned_provider_record_count
provider_record_count
newer_skipped_count
target_provider_record_count
older_seen_count
unknown_date_count
instrument_dictionary_count
mapping_failure_reason
```

注意：`provider_record_count` 表示目标日期 D 的 provider 记录数；`scanned_provider_record_count` 表示为找到目标日期而实际翻页看到的总记录数。这样可以区分“源里有新闻但不是目标日”和“目标日有新闻但映射失败”。

## 6. P0 优先级

P0-A：Qlib provider 依赖检查口径。

```text
明确配置项或文档约定的 provider_uri。
检查 day.txt 最新日期是否到最近完整交易日。
抽样确认 $close / $volume / $factor 可读。
如果基础 provider 过旧，QDC 当日 external factor 仍可采集，但不声明训练底座可用。
已落地：`qlib_provider.provider_uri` 默认指向 `~/.qlib/qlib_data/cn_data`；`qdc verify-qlib` 检查 day.txt、close/volume/factor 文件并通过 Qlib 抽样读取；控制台展示文件级状态。
```

P0-B：公告 metadata 主链路。

```text
CNINFO metadata 每日增量稳定。
SSE 作为补源观察。
PDF 下载默认关闭，按需要打开。
公告标题、发布时间、URL、instrument 映射和 raw_object 可追溯。
已落地：`crawl-daily` / `crawl-run` 默认 metadata-only；需要 PDF 时显式传 `--download-pdfs`。
```

P0-C：新闻源收敛。

```text
保留 1 到 2 个默认新闻补位源。
统计空结果率、解析失败率、重复率和映射率。
NBD 若继续不稳定，默认退出每日源，只保留手动 smoke。
已落地：默认新闻源收敛为 `sina_finance_news` 和 `eastmoney_roll_news`；crawler result 和 document bundle manifest 记录 empty_result_rate、duplicate_rate、parse_failed_rate、mapping_rate。
```

P0-D：外部因子输出。

```text
daily_news_factor / daily_announcement_factor 可重算。
因子按 publish_date 和交易日历对齐。
因子字段命名和 Qlib external handler 对齐。
已落地：`build-factors --factor-set all` 重算两张因子表；字段与 `QdcAlpha158WithExternal.DEFAULT_EXTERNAL_FIELDS` 对齐；`verify-qlib` 默认检查基础 `$close/$volume/$factor`。
```

## 7. P1/P2 扩展方向

P1：研报。

```text
优先接 metadata 和标题摘要。
保存 publish_time、机构、分析师、股票映射、URL、PDF hash。
先做研报数量、评级方向、风险提示和主题词因子。
```

P1：互动问答和投资者关系。

```text
优先公开、可追溯、无需登录的来源。
保留问题、回复、回复时间、公司、主题和情绪。
构建关注度、回复延迟、风险主题和新业务主题因子。
```

P2：公开舆情。

```text
只采公开合法内容。
不绕过登录、验证码或付费墙。
先做标题/摘要/热度 metadata，不保存敏感个人信息。
```

P2：法律处罚、招投标、招聘、专利。

```text
按行业相关性选择 1 类做最小可验证增量。
每次只新增一类来源，并补齐 raw、silver、factor、quality 和控制台预览。
```

## 8. 控制台口径调整

控制台仍可展示已有结构化表，但每日结论应改为：

```text
Qlib 基础 provider 状态
公告采集状态
新闻采集状态
外部因子构建状态
质量和异常源
```

旧的“日线行情、复权因子、涨跌停三项核心数据覆盖全部应采标的”不再作为 QDC 每日可用性的核心结论。基础行情可用性应来自 Qlib provider 检查。

## 9. 冻结和降级项

冻结：

```text
历史回补底座补齐
全 A 结构化每日采集
run-backfill 队列消费
回补控制台主入口
用 AkShare 免费新闻源做历史训练结论
```

降级为诊断：

```text
daily-pipeline
AkShare daily_bar / adj_factor / price_limit
Eastmoney 结构化备源
Sina realtime 结构化 fallback
```

## 10. 验收标准

近期验收不再要求全 A 基础行情由 QDC 采完，而是要求：

```text
Qlib provider 可用性检查口径清楚。
CNINFO 公告 metadata 单日可稳定入库。
至少一个新闻补位源单日可稳定入库。
daily_announcement_factor 和 daily_news_factor 可重算。
外部因子字段能被 Qlib handler 追加读取。
控制台不再误导用户去跑全 A 结构化采集。
```
