连接中

先看这三件事

总览页只回答一个问题：当前数据采集是不是在正常推进。

采集进度

每张卡表示一个数据集在某个来源和股票池下的回补批次总进度。

怎么读：绿色或完成表示这组任务已跑完；蓝色运行中表示正在写数据；橙色待执行表示排队；红色阻塞表示存在失败或超时任务，需要先处理。

任务状态

把所有控制表按状态汇总，用来发现失败、阻塞和未关闭质量问题。

数据水位

表示每个数据集已经覆盖到的日期范围。

最近运行

记录最近的 CLI 作业，例如回补、每日增量、因子加工和 Qlib 导出。

回补任务怎么看

回补任务是历史数据采集队列。先筛选数据集，再看失败和运行中的任务。

pending已经排队，等待 `run-backfill` 执行。
running正在采集或写入，长时间不动可能是陈旧任务。
failed失败任务需要查看最后错误，修复后用重试参数执行。
superseded原任务已被拆成更小任务，不再计入进度。

回补任务

适合定位哪段日期、哪批标的还没采完。

处理建议：长时间 running 可先停回补进程，再执行 `qdc recover-running --dataset <dataset> --older-than-minutes 15`；大任务过慢时可用 `qdc split-backfill --task-id <task_id> --batch-size 10` 拆小。

数据预览怎么看

这里先看覆盖，再按标的查看原始记录与加工后会进入研究和 Qlib 的日频因子。

覆盖情况看当前日期范围、源表行数、标的覆盖和原始源字段覆盖。
原始数据按日期一行展示全部原始源字段，新闻和公告以数量汇总并可展开。
处理后因子一张日频因子宽表，新闻和公告数量可点击展开明细。
标的搜索输入代码、简称或行业，可从下拉连续添加多个 instrument。

数据覆盖

合并展示采集源表覆盖和按标的的原始源字段覆盖。

下表按标的列出原始源字段覆盖；行情价格、涨跌和流动性、复权、涨跌停和停复牌字段映射到对应采集维度，新闻和公告字段显示已有明细数量。

标的数据预览

先选择标的，再按日期查看原始数据或处理后的日频因子；因子预览支持多标的排开对比。

质量检查怎么看

质量问题用来记录缺字段、空数据、日期缺口等异常。先处理未关闭的高严重级别问题。

open问题还存在，需要处理或重新跑质量检查。
closed问题已经关闭，通常只作历史记录。
severity严重级别越高，越应该优先看。

质量检查

定位哪个数据集、哪个实体出现质量异常。

Qlib 导出怎么看

这里确认当前 DuckDB 里的研究数据是否已经被导成 Qlib 可读的 provider 目录。

最近导出看导出日期范围、目标目录和文件数量。
导出文件看 calendars、features、instruments 等文件是否登记。
下一步验证用 `qdc verify-qlib` 检查 Qlib 是否能读取。
