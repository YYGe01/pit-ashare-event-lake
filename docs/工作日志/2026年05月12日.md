## 非结构化数据每日爬虫调研

- 新增 `docs/量化非结构化数据每日爬虫实施方案.md`，用于评估爬虫是否适合解决每日新增公告、新闻和舆情数据积累。
- 调研结论：爬虫适合解决每日新增公告和公开新闻补位，不适合作为多年历史新闻训练集的替代品。
- 推荐方案：采用 QDC `crawler-lite`，即 source adapter、crawl_task 控制表、raw append-only 留档、parser、silver 文档表和日频因子，不在第一阶段直接引入完整 Scrapy 项目。
- Source 优先级：先接 CNINFO 公告，再接交易所公告补源，再接 1-2 个公开新闻源；社交舆情源暂不作为 P0。
- 合规边界：不绕过登录、验证码、付费墙，不保存 cookie/token/账号密码，对版权不明确的新闻正文默认 metadata_only。

## 每日文档多源和文件优先存储

- 数据源硬门槛：每日公告和新闻主源/备用源必须能确认当天发布日期；包含历史混排且无法可靠过滤 `crawl_date` 的候选不启用。
- 新增默认公告备用源 `sse_announcement`，按 `beginDate=endDate` 请求上交所公告，并只接收 `SSEDATE == crawl_date` 的记录。
- 新增默认新闻备用源 `eastmoney_roll_news`，解析东方财富滚动新闻页中明确的 `YYYY-MM-DD HH:MM` 发布时间，并只接收 `publish_date == crawl_date` 的记录。
- 默认 `crawl-daily` 源调整为 `cninfo_announcement`、`sse_announcement`、`sina_finance_news` 和 `eastmoney_roll_news` 四个 crawler-backed 源。
- raw 侧新增直观文件包：`data/quant_data_center/raw/documents/<date>/<source_id>/<run>/manifest.json` 和 `records.jsonl`；DuckDB 继续保存控制表、`source_object` 索引、silver 表、因子和导出结果。
- `build-factors` 文档输入扩展到四个 crawler-backed 源，并按 `publish_date + instrument + normalized_title` 跨源去重后再计数，raw 和 silver 保留来源级证据。
- 控制台文档源过滤扩展到四个源，并允许预览 `raw_manifest` / `raw_records` 文件对象。
- 并行抓取评估：不同网站的 fetch 可以源级并行，但当前 adapter 抓取时仍会写 raw、bronze、`source_object` 和 silver；为保持 DuckDB 单写稳定性，当前先保持串行抓取。下一步应拆成 `fetch -> persist`，fetch 阶段并行写 `raw/documents`，persist 阶段单进程去重写 DuckDB。
- 已记录未启用候选：SZSE / BSE 公告、财联社、证券时报、中证网、上证报；后续只有确认稳定接口和明确发布日期字段后再启用。

- `qdc daily-pipeline` 的每日结构化任务不再规划 AkShare `announcement` / `news`；公告新闻每日新增只走 `crawl-daily` 的 crawler-backed 源。
