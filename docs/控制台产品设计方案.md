# 控制台产品设计方案

> 目标：让第一次接触项目的人也能通过 `qdc console` 判断数据采集是否正常、哪里卡住、下一步该做什么。

## 1. 设计原则

控制台不是给模型训练用的研究页面，而是给数据工程和回补监控用的操作观察台。页面信息必须先回答问题，再展示明细。

核心原则：

```text
先结论，后明细
先中文解释，后保留英文代码名
先状态和下一步，再给底层表格
只读页面不提供隐式写操作
默认展示少量关键数据，复杂明细通过筛选下钻
```

## 2. 信息架构

当前最佳方案是混合视角，而不是只按 dataset 或只按标的展示：

```text
总览             -> 我现在能不能放心让回补继续跑
回补任务         -> 哪个数据集、哪段日期、哪批标的卡住
数据预览         -> 某个表里的研究数据长什么样
质量检查         -> 哪些数据异常还没处理
Qlib 导出        -> 研究数据是否已经导成 Qlib provider
后续标的画像      -> 某只股票在所有日期上的行情、新闻、公告、因子时间线
```

为什么不是只按标的展示：

```text
回补和质量排障需要 dataset / task 视角，否则很难知道 daily_bar、news、announcement 哪条链路卡住。
研究验证需要标的视角，因为你关心某只股票每天的行情、新闻、公告和因子是否对齐。
所以控制台首页和排障页保持 dataset/task 视角，后续单独增加“标的画像”页做研究下钻。
```

## 3. 总览页

总览页只回答一个问题：当前数据采集是不是在正常推进。

页面结构：

```text
页面摘要
  说明这个页面用来判断当前采集是否正常

先看这三件事
  采集是否卡住
  数据覆盖到哪里
  Qlib 是否可用

关键指标
  统一研究层行数
  回补任务
  运行记录
  阻塞任务
  源文件索引
  水位记录
  Qlib 导出
  质量问题

采集进度
  每张卡 = 一个 dataset + source_id + universe 的任务组
  显示完成率、日期范围、成功、待执行、运行中、失败
  给出下一步建议

任务状态 / 数据水位 / 最近运行
  给排障者看更细明细
```

采集进度的状态解释：

```text
complete  全部任务成功，可以继续 build-factors / sync-parquet / export-qlib
running   正在运行，正常观察即可
pending   已排队，等待 run-backfill 消费
blocked   有 failed 或 stale running，需要先处理
failed    任务失败，查看 last_error 后重试
```

覆盖统计和缺失分析不放在总览页。总览页只保留采集健康、回补进度、任务状态、水位和最近运行，避免把“系统是否在跑”和“数据是否完整”混在同一屏。

## 4. 回补任务页

这个页面用于定位采集队列里的具体任务。

新手优先看：

```text
status       当前任务状态
dataset      哪类数据，例如 daily_bar、news、announcement
start/end    这条任务负责的日期范围
symbols      这条任务负责的标的批次
last_error   失败原因
updated_at   最近更新时间
```

处理建议：

```bash
qdc recover-running --dataset <dataset> --older-than-minutes 15
qdc split-backfill --task-id <task_id> --batch-size 10
qdc run-backfill --dataset <dataset> --retry-failed
```

## 5. 数据预览页

这个页面负责回答“已经采到的数据覆盖怎样、缺在哪里、具体记录长什么样”。页面通过三个分段 tab 展示覆盖统计、原始数据和处理后因子；原始数据和处理后因子 tab 顶部提供可搜索下拉框，支持输入 `SH600000`、`600000`、股票名称或行业后选择标的。

```text
数据覆盖：合并展示当前日期范围、源表行数、标的覆盖和按标的核心维度覆盖分数
原始数据预览：读取 qdc_meta.source_object 登记的 raw 留档，只展示后续因子加工会用到的字段
处理后因子预览：读取 qdc_silver 里已经按交易日和标的对齐的研究字段，用一张宽表展示全部因子
```

### 5.1 覆盖统计口径

参考标的优先级：

```text
1. 最新 universe_constituent 成分
2. config/quant_data_center.yaml 里的 universes 配置
3. silver 表里已有 instrument 的并集
```

参考交易日优先级：

```text
1. trade_calendar 里的开市日
2. daily_bar / adj_factor / price_limit 的交易日并集
```

核心维度覆盖分数只判定：

```text
daily_bar     日线行情
adj_factor    复权因子
price_limit   涨跌停价格
```

覆盖页不再展示独立的“缺口”维度。按标的明细里，`daily_bar`、`adj_factor`、`price_limit` 这些必备日频列显示已覆盖/应覆盖，例如 `484/484`；`stock_basic`、`universe_constituent` 这类必备静态维度显示 `1/1` 或 `0/1`。`news`、`announcement` 和 `trade_status` 当前没有稳定分母，只展示已有记录条数或天数，不把没有事件直接判成缺失。`daily_news_factor`、`daily_announcement_factor` 属于处理后因子，不进入覆盖缺失总览。

操作顺序：

```text
1. 切到“覆盖情况”tab，确认当前日期范围、源表覆盖和核心维度覆盖分数
2. 切到“原始数据预览”或“处理后因子预览”
3. 在标的搜索框输入代码、名称或行业，从下拉里选择 instrument
4. 输入开始和结束日期，避免一次拉太多行
```

原始数据预览的典型用途：

```text
daily_bar / adj_factor / price_limit / trade_status  按日期合并看价格、成交、复权、涨跌停和交易状态
news / announcement                                  同一天只显示数量，点击数量展开标题、链接和来源
stock_basic / universe_constituent                   看代码、名称、交易所、行业、股票池和权重
一张原始数据宽表                                  一行一个日期，横向查看同一天采集到的有效字段
```

原始预览不要直接展示 JSON、raw 文件索引、记录数或缺失统计。上游返回字段可能包含嵌套结构、调试参数和无关字段，对新手不友好，也不利于判断“这些数据后面怎么变成因子”。页面只保留一张按日期聚合的数据宽表，列出因子链路需要的字段：

```text
标的识别：instrument、symbol、name、exchange、industry
时间字段：date，一行一个日期
行情字段：open、high、low、close、volume、amount
约束字段：adj_factor、limit_up、limit_down、trade_status、halt_reason
文本字段：news_count、announcement_count，点击数量展开 title、url、source
```

处理后因子预览的输出：

```text
顶部摘要：当前页交易日数量、核心完整天数、当前页新闻明细条数、当前页公告明细条数
因子分类：行情价格、复权和交易限制、新闻相关因子、公告相关因子、来源追踪
因子宽表：每行一个 trade_date，每列一个处理后的研究字段，横向滚动查看全部因子
分页：按交易日分页，默认使用页面选择的行数作为 page_size；数据量较大的通用表格默认每页展示 5 行并提供上一页/下一页
可展开明细：news_count 和 announcement_count 默认只显示数量，点击数量展开当天多个新闻或公告标题、发布日期和来源
```

宽表是当前最佳处理方式：因子研究的核心动作是横向比较同一交易日的所有字段，而不是把新闻、公告、行情拆成多个小表来回对照。分类卡只负责解释列归属，不打断宽表阅读。

接口边界：

```text
/api/instruments              负责标的下拉搜索
/api/raw-instrument-preview   负责按 instrument 读取 raw 留档并转换成原始数据宽表输入
/api/factor-preview           负责按 instrument 合并多个日频表，并返回可按交易日展开的文本明细
/api/dataset-preview          保留为兼容接口，不再作为前端主入口
```

## 6. 质量检查页

这个页面用于处理数据异常。

优先级：

```text
open 且 severity 高的问题优先处理
closed 只作历史记录
message 是给人的说明，entity_key 通常指向具体标的或日期
```

## 7. Qlib 导出页

这个页面用于确认 QDC 数据是否已经交给 Qlib。

判断顺序：

```text
最近导出是否 success
导出的日期范围是否覆盖研究区间
provider_uri 是否是预期目录
导出文件是否登记到 source_object
最后执行 qdc verify-qlib 验证 Qlib 可读
```

## 8. 后续标的画像页

后续应新增“标的画像”页，作为研究验证视角。

推荐交互：

```text
输入标的 + 日期范围
顶部显示该标的覆盖天数、最早/最晚交易日、新闻/公告数量
主时间线按 trade_date 展示行情、交易状态、新闻因子、公告因子
点击某天展开当天新闻标题、公告标题和事件标签
默认只加载最近 250 个交易日，更多历史分页或按日期筛选
```

这个页面不替代总览和回补任务页，因为标的视角看不出整个 dataset 的采集队列是否健康。
