# quant_data_center 数据流阅读指南

> 适合第一次阅读本项目的人。本文从数据流角度解释当前项目在做什么、每一步吃什么输入、产出什么格式，以及这些数据最后怎么给 Qlib 使用。
> 2026-05-14 口径更新：当前主线已经从“QDC 自建完整基础行情 provider”调整为“Qlib `cn_data` 提供基础行情，QDC 提供非结构化 external factors”。文中保留的 `daily_bar`、`adj_factor`、`export-qlib` 全量 provider 说明用于理解历史能力、smoke 和兼容链路，不是默认每日采集目标。

## 0. 术语对照和阅读约定

本文尽量先用中文术语说明概念，并在第一次出现时保留英文名，方便你回到代码、配置和命令里查找。命令参数、Python 标识符、数据库字段、表名、目录名和 Qlib 固有名称仍保持英文。

常见对照：

```text
数据集 dataset                 一类要采集、清洗或导出的数据，例如 daily_bar、announcement
数据来源 source/provider        上游数据提供方，例如 AkShare；Qlib provider 指 Qlib 可读数据目录
股票池 universe                一组标的，例如 csi300
标的 instrument                项目内部统一股票代码，例如 SH600000
上游代码 symbol                上游接口需要的代码，例如 600000
任务 task                      回补或日更中的一个可恢复执行单元
批次 batch                     一组标的或日期组成的任务切片
水位 watermark                 某个数据集已经完成到的日期范围
原始留档层 raw                 保存上游原始响应和请求信息
上游快照层 bronze              保存贴近上游字段的结构化快照
统一研究层 silver              保存统一字段、日期和标的后的研究表
研究宽表层 gold                保存可直接分析或导出的日频宽表

冒烟验证 smoke                 小样本快速验证，证明链路能跑通

特征 feature                   模型可消费的输入字段
标签 label                     模型训练要预测的目标字段
命名市场 market                Qlib 里的标的集合名称
```

## 1. 当前状态

当前仓库的新主线是非结构化采集和 Qlib external factors：

```text
Qlib cn_data               由上层 E:\code\qlib 或社区 release 维护
公告/新闻 crawl-daily       已完成基础版
raw/bronze/silver 写入      已完成
daily_news_factor           已完成基础版
daily_announcement_factor   已完成基础版
sync-parquet / quality      已完成基础版
Qlib handler 外部因子读取    已有示例
控制台观察                  已有基础版
```

当前需要继续加强：

```text
Qlib provider 新鲜度检查
CNINFO / SSE 公告 metadata 稳定性
新闻源收敛和源级稳定性统计
公告、新闻、研报、舆情等 external factor 覆盖
external factors 与 Qlib 日历、instruments 对齐
Qlib 基准实验和外部因子增益评估
```

历史结构化链路、回补队列和全量基础 provider 导出仍保留，但只作为 smoke、诊断和应急补数使用。除非明确要求，不再默认推进 `plan-backfill`、`run-backfill` 或全 A `daily-pipeline`。

本地只读控制台 `qdc console` 后续应重点展示 Qlib provider 状态、公告/新闻采集状态、external factor 构建状态、源级失败和质量问题；历史回补任务只作为诊断视图保留。

## 2. 一句话架构

```text
Qlib / 社区 cn_data / Qlib 增量脚本
  -> 基础行情、复权因子、交易日历、instruments

公告 / 新闻 / 研报 / 舆情等来源
  -> qdc crawl-daily 执行每日文档采集
  -> 原始留档层 raw
  -> 上游快照层 bronze
  -> 统一研究层 silver
  -> 因子引擎 factor_engine 生成日频 external factors
  -> 研究宽表层 gold / external factor 文件
  -> Qlib handler 追加读取
  -> Qlib 训练、回测、分析
```

边界很重要：

```text
当前仓库 quant_data_center
  负责非结构化采集、清洗、事件标准化、因子加工、质量检查、external factor 导出

E:\code\qlib
  负责 Qlib 框架源码、cn_data 下载/替换/增量更新、DatasetH、模型训练和回测

当前仓库不做
  每日下载社区 cn_data、全 A 基础行情主库维护、模型训练、组合回测、实盘下单、终端交易
```

## 4. 统一标的格式

项目内部统一使用 Qlib 友好的 A 股代码：

```text

SZ000001
SZ300750
BJ430047
```

上游 AkShare 可能需要纯数字代码，例如：

```text

000001
300750
```

## 6. 股票池数据流

股票池（universe）是一组标的，例如 `csi300`。

命令：

```bash
qdc refresh-universe --universe csi300 --snapshot-date 2026-05-11
```

输入：

```text
universe = csi300
snapshot_date = 2026-05-11
source_id = akshare
```

上游返回样例：

```json
{
  "品种代码": "600000",
  "品种名称": "浦发银行",
  "纳入日期": "2026-05-11",
  "权重": 0.54
}
```

写入统一研究层表 `qdc_silver.universe_constituent`：

```text
universe      snapshot_date  instrument  symbol  exchange  name      weight  source_id
csi300        2026-05-11     SH600000    600000  SH        浦发银行  0.54    akshare
csi300        2026-05-11     SZ000001    000001  SZ        平安银行  0.38    akshare
```

后续 `plan-backfill --universe csi300` 会优先用这里的最新成分快照展开标的列表。

## 7. 历史回补任务流

### 7.1 规划任务

命令：

```bash
qdc plan-backfill \
  --dataset daily_bar \
  --source-id akshare \
  --universe csi300 \
  --start 2026-05-01 \
  --end 2026-05-03 \
  --batch-size 2 \
  --chunk-days 2
```

输入参数：

```text
数据集 dataset = daily_bar
数据来源 source_id = akshare
股票池 universe = csi300
日期范围 date_range = 2026-05-01 到 2026-05-03
批次大小 batch_size = 每个任务最多 2 个标的
日期切片 chunk_days = 每个任务最多 2 天
```

输出到 `qdc_meta.backfill_task`：

```text
task_id   dataset    source_id  universe  start_date  end_date    symbol_batch_json              status
uuid-001  daily_bar  akshare    csi300    2026-05-01  2026-05-02  ["SH600000","SZ000001"]        pending
uuid-002  daily_bar  akshare    csi300    2026-05-03  2026-05-03  ["SH600000","SZ000001"]        pending
uuid-003  daily_bar  akshare    csi300    2026-05-01  2026-05-02  ["SZ300750","SH600519"]        pending
```

这一步只生成计划，不采集真实数据。

### 7.2 执行任务

命令：

```bash
qdc run-backfill --dataset daily_bar --limit-tasks 4
```

任务执行前：

```text
status = pending
attempt_count = 0
```

任务执行中：

```text
status = running
attempt_count = 1
```

任务成功后：

```text
status = success
last_error = null
updated_at = 当前时间
```

任务失败后：

```text
status = failed
last_error = 上游异常或本地写入异常
```

重试失败任务：

```bash
qdc run-backfill --dataset daily_bar --retry-failed --limit-tasks 4
```

如果一个进程中断后留下长时间 `running` 的任务，可以先恢复为失败态：

```bash
qdc recover-running --dataset daily_bar --older-than-minutes 15
```

如果一个任务的标的批次过大，也可以拆成更小的待执行子任务：

```bash
qdc split-backfill --task-id <task_id> --batch-size 10
```

原任务会变成：

```text
status = superseded
last_error = split into 3 subtasks with batch_size 10
```

新的子任务会继续等待 `qdc run-backfill` 执行：

```text
status = pending
symbol_batch_json = ["SH600000"]
```

## 8. 原始留档层 raw

原始留档层保存上游原始响应和请求元数据，用来审计和以后重算。

以 `daily_bar` 为例，原始 JSON 形态大致是：

```json
{
  "function": "stock_zh_a_hist",
  "params": {
    "symbol": "600000",
    "period": "daily",
    "start_date": "20260501",
    "end_date": "20260503",
    "adjust": ""
  },
  "records": [
    {
      "日期": "2026-05-01",
      "股票代码": "600000",
      "开盘": 10.10,
      "收盘": 10.30,
      "最高": 10.40,
      "最低": 10.00,
      "成交量": 1234567,
      "成交额": 12678900.0
    }
  ]
}
```

原始留档文件路径示例：

```text
data/quant_data_center/raw/daily_bar/2026-05-01/stock_zh_a_hist_SH600000_2026-05-01_2026-05-03.json
```

同时登记到 `qdc_meta.source_object`：

```text
dataset    source_id  layer  uri                                                                 content_hash  size_bytes
daily_bar  akshare    raw    data/quant_data_center/raw/daily_bar/.../stock_zh_a_hist_...json    sha256...     2048
```

原始留档层采用追加写入，不应该覆盖历史对象。

## 9. 上游快照层 bronze

上游快照层保存结构化后的上游结果，字段尽量贴近上游原始字段。

`daily_bar` 上游快照 Parquet 行样例：

```text
日期          股票代码  开盘   收盘   最高   最低   成交量    成交额
2026-05-01   600000    10.10  10.30  10.40  10.00  1234567   12678900.0
```

路径示例：

```text
data/quant_data_center/parquet/bronze/daily_bar/2026-05-01/stock_zh_a_hist_SH600000_2026-05-01_2026-05-03.parquet
```

上游快照层的作用：

```text
保留上游字段
方便排查上游字段漂移
方便从上游快照层重新标准化到统一研究层
```

## 10. 统一研究层 silver

统一研究层是统一口径研究表。这里字段名、日期、股票代码都已经标准化。

### 10.1 日线行情 daily_bar

输入来自原始留档层或上游快照层的行情数据。

输出表：`qdc_silver.daily_bar`

```text
trade_date  instrument  open   high   low    close  pre_close  volume   amount      vwap   source_id
2026-05-01  SH600000    10.10  10.40  10.00  10.30  10.05      1234567  12678900.0  10.27  akshare
```

`vwap` 是成交均价，通常由成交额和成交量推导。Qlib Alpha158 默认会用到 `$vwap`。

### 10.2 复权因子 adj_factor

`adj_factor` 是复权因子。股票分红、送转、拆股、配股等权益变动会让原始价格出现断点，复权因子用于把不同日期的价格调整到可比较口径。Qlib 导出时会把这个字段写成 `factor.day.bin`。

输出表：`qdc_silver.adj_factor`

```text
trade_date  instrument  adj_factor  factor_type                    source_id
2026-05-01  SH600000    0.823456    qfq_close_ratio_v0_inferred    akshare
```

### 10.3 涨跌停价格 price_limit

`price_limit` 保存每日涨停价、跌停价和规则口径，用于检查行情边界，也可以作为研究因子或过滤条件。

输出表：`qdc_silver.price_limit`

```text
trade_date  instrument  limit_up  limit_down  prev_close  limit_rule                         source_id
2026-05-01  SH600000    11.06     9.05        10.05       main_board_normal_10pct_v0_inferred akshare
```

### 10.4 交易状态 trade_status

`trade_status` 保存标的在某个交易日是否正常交易、停牌或有其他交易状态。

输出表：`qdc_silver.trade_status`

```text
trade_date  instrument  trade_status  halt_reason  source_update_time  source_id
2026-05-01  SH600000    normal        null         2026-05-01          akshare
```

### 10.5 公告 announcement

公告只保留标题、日期、标的和链接。正文暂不进入最小可用版本 MVP。

输出表：`qdc_silver.announcement`

```text
announcement_id  publish_date  instrument  title                    url                          source_id
sha256...        2026-05-01    SH600000    年度权益分派实施公告      https://example.test/a/1      akshare
```

### 10.6 新闻 news

新闻同样先做标题级入库。

输出表：`qdc_silver.news`

```text
news_id   publish_date  instrument  title                              url                          source_id
sha256... 2026-05-01    SH600000    公司签订重大订单增长                https://example.test/n/1      akshare
sha256... 2026-05-01    SH600000    公司被立案调查存在退市风险          https://example.test/n/2      akshare
```

## 12. 因子引擎 factor_engine 数据流

命令：

```bash
qdc build-factors --factor-set all --start 2026-05-01 --end 2026-05-03
```

当前支持：

```text
news_v1             新闻因子版本 1
announcement_v1     公告因子版本 1
all                 全部当前可用因子
```

### 12.1 新闻情绪和事件因子例子

输入表：`qdc_silver.news`

```text
publish_date  instrument  title
2026-05-10    SH600000    公司签订重大订单增长
2026-05-11    SH600000    公司被立案调查存在退市风险
```

如果 `2026-05-10` 不是交易日，`2026-05-11` 是交易日，系统先对齐到下一个开市日：

```text
2026-05-10 新闻 -> trade_date = 2026-05-11
2026-05-11 新闻 -> trade_date = 2026-05-11
```

情绪规则是可复现的事件规则。每条文本先被规则分类成事件类型、情绪分和重要性分，再聚合到“标的-日期”：

```text
event_types 事件类型：contract 合同 / regulatory 监管 / litigation 诉讼 / buyback 回购 / performance_positive 业绩向好 ...
sentiment_score 情绪分：-1 到 1
importance_score 重要性分：0 到 1
weighted_sentiment 加权情绪分 = sentiment_score * importance_score
```

第一条：

```text
标题：公司签订重大订单增长
命中：订单、增长
event_types 事件类型 = contract 合同 + growth 增长
sentiment_score 情绪分 > 0
growth_event 增长事件 = 1
contract_event 合同事件 = 1
risk_event 风险事件 = 0
financing_event 融资事件 = 0
```

第二条：

```text
标题：公司被立案调查存在退市风险
命中：立案调查、退市、风险
event_types 事件类型 = regulatory 监管 + risk 风险
sentiment_score 情绪分 < 0
growth_event 增长事件 = 0
risk_event 风险事件 = 1
regulatory_event 监管事件 = 1
financing_event 融资事件 = 0
```

## 15. Qlib 外部因子导出和历史 provider 导出流

当前目标是在 Qlib `cn_data` 基础上追加 QDC external factors。下面的完整 provider 导出命令和基础字段清单保留用于历史 smoke、兼容验证和代码阅读，不是默认每日主线。

命令：

```bash
qdc export-qlib \
  --start 2026-05-01 \
  --end 2026-05-03 \
  --provider-uri data/quant_data_center/qlib/cn_data \
  --market-name qdc_smoke
```

历史完整 provider 导出输入来自：

```text
qdc_silver.daily_bar                    日线行情，历史/诊断
qdc_silver.adj_factor                   复权因子，历史/诊断
qdc_silver.price_limit                  涨跌停价格，历史/诊断
qdc_silver.daily_news_factor            新闻日频因子
qdc_silver.daily_announcement_factor    公告日频因子
```

历史 smoke 导出的 Qlib 数据目录：

```text
data/quant_data_center/qlib/cn_data/
├── calendars/                  交易日历目录
│   └── day.txt
├── instruments/                标的列表目录
│   ├── all.txt
│   └── qdc_smoke.txt
└── features/                   特征字段目录
    └── sh600000/
        ├── open.day.bin                         开盘价
        ├── high.day.bin                         最高价
        ├── low.day.bin                          最低价
        ├── close.day.bin                        收盘价
        ├── vwap.day.bin                         成交均价
        ├── volume.day.bin                       成交量
        ├── amount.day.bin                       成交额
        ├── factor.day.bin                       复权因子
        ├── limit_up.day.bin                     涨停价
        ├── limit_down.day.bin                   跌停价
        ├── news_count.day.bin                   新闻数量
        ├── news_sentiment_mean.day.bin          新闻情绪均值
        ├── news_positive_count.day.bin          正面新闻数量
        ├── news_negative_count.day.bin          负面新闻数量
        ├── news_growth_count.day.bin            增长类新闻数量
        ├── news_risk_count.day.bin              风险类新闻数量
        ├── news_financing_count.day.bin         融资类新闻数量
        ├── announcement_count.day.bin           公告数量
        ├── announcement_risk_count.day.bin      风险类公告数量
        ├── announcement_financing_count.day.bin 融资类公告数量
        └── announcement_operation_count.day.bin 经营类公告数量
```

`calendars/day.txt` 样例：

```text
2026-05-01
2026-05-02
2026-05-03
```

`instruments/qdc_smoke.txt` 样例：

```text
sh600000	2026-05-01	2026-05-03
sz000001	2026-05-01	2026-05-03
```

Qlib `.day.bin` 是二进制浮点数序列。当前写法：

```text
第 1 个浮点数 = 该标的在全局交易日历 calendar 里的起始下标 index
后续浮点数 = 每个交易日的字段值
```

例如 `close.day.bin` 逻辑值可以理解为：

```text
[0.0, 10.30, 10.45, 10.20]
```

含义：

```text
start_index = 0
2026-05-01 close = 10.30
2026-05-02 close = 10.45
2026-05-03 close = 10.20
```

## 17. 一个完整小例子

假设要处理 `SH600000` 在 `2026-05-11` 的数据。

### 17.1 基础行情

当前默认从 Qlib `cn_data` 读取基础行情、复权因子、交易日历和 instruments。下面的上游行情例子用于解释 QDC 历史结构化分支如何写入 `daily_bar`，不是默认每日采集路线。

上游返回：

```json
{
  "日期": "2026-05-11",
  "股票代码": "600000",
  "开盘": 10.10,
  "收盘": 10.30,
  "最高": 10.40,
  "最低": 10.00,
  "成交量": 1234567,
  "成交额": 12678900.0
}
```

统一研究层输出：

```text
trade_date  instrument  open   high   low    close  volume   amount      vwap
2026-05-11  SH600000    10.10  10.40  10.00  10.30  1234567  12678900.0  10.27
```

### 17.2 上游新闻

统一研究层新闻输入：

```text
publish_date  instrument  title
2026-05-10    SH600000    公司签订重大订单增长
2026-05-11    SH600000    公司被立案调查存在退市风险
```

交易日对齐：

```text
2026-05-10 不是交易日 -> 2026-05-11
2026-05-11 是交易日 -> 2026-05-11
```

因子输出：

```text
trade_date  instrument  news_count  news_sentiment_mean  news_positive_count  news_negative_count  news_growth_count  news_risk_count
```

### 17.3 Qlib 最终可见字段

导出后，Qlib 看到的是数值字段：

```text

2026-05-11  SH600000    10.30   10.27  2.0          0.0                   1.0                 1.0
```

这就是“新闻变成 Qlib 可用特征”的完整路径。

## 18. 前端监控应该看什么

当前项目已经提供一个本地只读控制台：

```bash
qdc console --host 127.0.0.1 --port 8765
```

默认访问：

```text
http://127.0.0.1:8765/
```

这个控制台直接用只读 DuckDB 连接读取本地状态，不触发采集、不执行回补、不写库，适合观察 Qlib provider 新鲜度、文档源采集、external factor 构建和历史诊断任务。

控制台的产品设计目标不是把数据库表原样搬到页面上，而是先用中文告诉你当前是否健康、哪里卡住、下一步做什么。页面设计细节见 `docs/控制台产品设计方案.md`。

总览页优先保留 Qlib provider 状态、公告/新闻采集健康、外部因子构建、水位和最近运行。覆盖和缺失分析放在数据预览页的“覆盖情况”tab，避免把采集进度和数据体检混在同一屏。

控制台的数据概览会额外统计：

```text
Qlib provider：provider_uri、最新交易日、features 和 $factor 抽样状态。
文档覆盖：announcement、news 等源表行数、数据源、日期范围和映射标的数。
事件稀疏性：news、announcement 只统计已有记录或天数，不把没有事件判成缺失。
处理后因子：daily_news_factor、daily_announcement_factor 在处理后因子预览里展示，并检查与 Qlib 交易日历对齐。
```

数据预览页有三类信息：

```text
覆盖情况 tab：来自 /api/overview 的 data_coverage，用来确认当前日期范围、文档源覆盖、Qlib provider 状态和 external factor 对齐状态。
原始数据预览：读取 /api/raw-instrument-preview，按标的匹配 qdc_meta.source_object 中的 raw 留档，只展示后续因子加工会用到的字段。
处理后因子预览：读取 /api/factor-preview，按 trade_date 合并 Qlib 基础字段引用、新闻因子、公告因子和后续外部因子，并用宽表展示。
标的搜索：读取 /api/instruments，支持代码、名称、行业和股票池搜索。
```

数据量较大的前端表格默认每页展示 5 行，并在表格下方显示上一页/下一页；数据量较小的表格不额外显示分页控件。

预览交互口径：

```text
原始数据预览只展示一张按日期聚合的数据宽表，不展示 raw 文件索引、记录数、缺失统计或底层 JSON。
原始预览一行一个日期；同一天多条新闻或公告只显示数量，点击数量展开标题、发布日期、来源和链接。
处理后因子预览也展示一张日频因子宽表，news_count 和 announcement_count 默认只显示数量并可展开明细。
```

前端如果要监控回补进度，推荐先读这些表：

## 19. 当前还没有做什么

当前没有直接把非结构化正文喂给 Qlib。

