# 每日非结构化采集与 Qlib 外部因子实施计划

> 创建日期：2026-05-12
> 重写日期：2026-05-14
> 当前定位：这是 QDC 当前每日采集状态和下一步的唯一入口。结构化基础行情由 Qlib `cn_data` 维护，QDC 默认聚焦公告、新闻、研报、舆情等非结构化数据和 external factors。

## 1. 一句话结论

当前项目主线已经调整为：

```text
Qlib / 社区 cn_data / Qlib 增量脚本
  -> 维护基础行情、复权因子、交易日历和 instruments

QDC
  -> 采集非结构化数据
  -> 归一化为 announcement / news / 后续 research_report / sentiment 等表
  -> 构建 daily external factors
  -> 对齐到 Qlib provider_uri
```

因此，QDC 不再以“全 A 日线、复权、涨跌停每日采集”为默认目标。既有 `daily-pipeline` 和 AkShare 结构化 collector 保留为历史能力、smoke、诊断和应急补数，不再作为 P0 主线。

当前默认入口：

```text
qdc crawl-daily       非结构化文档每日采集
qdc build-factors     文本事件日频因子
qdc sync-parquet      DuckDB 到 Parquet 同步
qdc quality           基础质量检查
qdc console           本地观察面
```

```text

标题到 instrument 映射使用预构建股票索引，避免每条新闻循环全市场股票做正则匹配。
```

### 非结构化日期扫描算法

非结构化源按日期口径分两类处理，后续新增研报、舆情、互动问答等源也默认套用这个判断框架。

第一类是来源支持精确日期查询的源，例如 `cninfo_announcement` 和 `sse_announcement`：

```text
请求参数必须显式传目标日期 D。
如果来源返回总页数，默认翻完所有页。
只有显式 smoke / 调试时才传 --max-pages。
如果 --max-pages 小于来源总页数，manifest 必须记录 date_scan_complete=false 和 date_scan_stop_reason=max_pages。
silver 只接受来源日期字段等于 D 的记录。
```

第二类是倒序滚动列表源，例如 `eastmoney_roll_news` 和 `sina_finance_news`：

```text
目标日期 D 的时间窗为 [D 00:00:00, D+1 00:00:00)。
默认使用快速定位扫描，而不是从最新页线性扫到目标日。
先抓第 1 页；如果整页都晚于 D，则按 2、4、8、16... 指数探测。
找到第一个不再整页晚于 D 的页后，在相邻探测区间内二分定位边界页。
从边界页向前回看 2 页，再顺序扫描目标日窗口，防止滚动页轻微乱序。
publish_time >= D+1 的记录判为 newer，只进 raw/bronze，不进 silver。
D <= publish_time < D+1 的记录判为 target，才进入映射、document records、silver 和因子。
publish_time < D 的记录判为 older。
一旦已经命中过 target，并连续看到 2 个整页 older，再停止，防止页面轻微乱序。
如果第一页或扫描过程中已经整页早于 D 且从未命中过 target，认为目标日无可用记录并停止。
默认不传 --max-pages，由 hard_max_pages 防止无限翻页；当前 hard_max_pages=200。
如果打到 --max-pages / hard_max_pages / source_timeout，manifest 必须记录 date_scan_complete=false。
```

滚动源 manifest 必须保留这些排障字段：

```text
date_scan_strategy
target_date / target_start / target_end_exclusive
date_scan_complete
date_scan_stop_reason
date_scan_pages_scanned
date_scan_fetch_strategy
date_scan_probe_pages
date_scan_sequential_start_page
date_scan_first_target_page / date_scan_last_target_page
scanned_provider_record_count
provider_record_count
newer_skipped_count
target_provider_record_count
older_seen_count
unknown_date_count
instrument_dictionary_count
mapping_failure_reason
```

注意：`provider_record_count` 表示目标日期 D 的 provider 记录数；`scanned_provider_record_count` 表示为找到目标日期而实际翻页看到的总记录数。这样可以区分“源里有新闻但不是目标日”和“目标日有新闻但映射失败”。

### 代理策略

本地 QDC 默认不读取 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、`NO_PROXY` 及对应小写环境变量。原因是本地实测中不稳定主要来自环境变量代理，表现为交易所和新闻源超时、断连或返回不一致。默认配置为：

```yaml
runtime:
  use_environment_proxy: false
```

如确实需要走公司网络代理或专用代理，可显式改成 `true`，但应优先固定一个可靠出口，而不是代理池。代理池会引入 IP 质量、封禁、页面差异、合规和排障复杂度。

## 6. 日频预测和调仓采集参考

适用场景：Qlib 日频策略，一天预测一次，一天调仓一次。QDC 的每日采集调度应服务这个可见性口径，而不是把某一次盘后快照直接当最终训练数据。

当前默认定时结论：

```text
默认把“次日凌晨采前一自然日”作为 final 封账口径。

例如：
2026-05-14 18:00 采 2026-05-14，只能算截至 18:00 可见的 provisional 版本。
2026-05-15 凌晨或早晨再采 2026-05-14，才作为 2026-05-14 的 final 候选版本。

如果只保留一次定时任务，优先选择 T 日凌晨/早晨采 T-1，而不是 T-1 当天傍晚采 T-1。
如果需要 T 日开盘前预测，默认使用 T 07:30 采 T-1 并封账。
如果不做开盘前预测，只做离线研究，T 01:00-03:00 采 T-1 也可以作为低成本默认。
```

当前实现注意事项：

```text
crawl-daily 对同一 source_id、dataset、crawl_date 和 parser request 成功任务会跳过。
因此，在未实现 force 重采或 final rerun 机制前，不建议同一天先跑 provisional、次日再用完全相同任务封账同一日期。
最小稳定方案是只在 T 日凌晨/早晨采 T-1，把这次采集作为该自然日的 final。
若未来需要盘后 preview + 次日 final 两版，应补充 --force 或独立 final 任务机制。
```

推荐默认节奏：

```text
T-1 15:00        A 股收盘。
T-1 15:45        当日初扫，采 T-1 公告和新闻，生成 provisional 因子。
T-1 18:30        晚间补扫，覆盖一批盘后公告和新闻。
T-1 22:30        夜间补扫，覆盖多数晚间披露，作为次日预测前的主要候选版本。
T 07:30          最终补扫 T-1，并扫描隔夜到开盘前事件，生成 final 候选版本。
T 08:20          build-factors、sync-parquet、quality，确认 Qlib provider 新鲜度。
T 08:30-08:50    用 T-1 及以前可见数据预测 T 日收益，生成目标持仓。
T 09:35-10:00    开盘后避开最初几分钟冲击，执行日频调仓。
```

最小可行定时：

```text
T-1 22:30        采 T-1，当作夜间 provisional 版本。
T 07:30          重采 T-1 并封账，补齐 22:30 之后到预测 cutoff 前观察到的数据。
```

可见性硬规则：

```text
因子日期归属仍使用 publish_date。
是否能用于某次预测必须看 observed_at / collect_time / asof cutoff。
T-1 18:00 采到的数据只能算 provisional，不能视作最终完整版本。
T 07:30 之后、预测 cutoff 之后才观察到的数据，不进入 T 日开盘前预测特征。
T 日收盘后发布或采集的数据，不能用于预测 T 日收益，只能用于 T+1 或之后。
回测、训练、实盘预测必须使用同一个 cutoff 口径，否则容易引入未来函数。
```

采集版本建议：

```text
raw 继续追加保存每次观察证据。
silver 按 source_id、URL、发布时间、标题 hash 或正文 hash 做幂等去重。
gold external factors 应能区分 provisional / final，或至少记录 factor_run 的 asof_cutoff。
每日 07:30 任务负责封账最近完整交易日，周末和节假日可每天扫描最近 3 个自然日防迟到披露。
```

### 云端自动运行建议

本项目当前采用 DuckDB 本地文件、raw 文件包、Parquet 和 Qlib provider 目录，最小改造的云端方案不是先上云数据库，而是先把“笔记本本地运行”迁移成“云服务器常驻运行”。

推荐第一阶段：

```text
一台小型云服务器/VPS
  -> 安装 conda 和 ai-trader 环境
  -> 拉取本仓库
  -> data/quant_data_center 放在云服务器数据盘
  -> cron 或 systemd timer 每天按 Asia/Shanghai 时间运行采集脚本
  -> 任务完成后把 raw、parquet、qlib 和 qdc.duckdb 备份到对象存储或网盘
  -> 笔记本只负责远程查看、拉取结果和本地分析，不再负责定时开机
```

默认定时脚本口径：

```text
计算 target_date = 今天 - 1 天。
qdc crawl-daily --date <target_date>
qdc build-factors --factor-set all --start <target_date> --end <target_date>
qdc sync-parquet --layer all
qdc quality --start <target_date> --end <target_date>
```

云端存储建议：

```text
短期：DuckDB 继续放在云服务器本地数据盘，raw/parquet/qlib 文件也放本地盘。
备份：每天采集结束后复制到对象存储，例如 S3/OSS/COS/R2，或用 rclone 同步到云盘。
同步到笔记本：从对象存储或云盘拉取 data/quant_data_center 的备份副本。
```

不建议第一阶段直接改云数据库：

```text
当前代码读写的是本地 DuckDB 文件和本地文件目录。
PostgreSQL/RDS 这类云数据库不能直接替代 raw 文件、Parquet 和 Qlib provider。
如果要上云数据库，需要先重构 storage/database.py，并把 raw/parquet 另放对象存储。
```

不建议把 GitHub Actions 作为主采集运行环境：

```text
Actions 的定时适合 CI 或短任务 smoke，不适合作为训练数据主采集底座。
runner 是临时环境，本地 DuckDB 和 raw 文件默认不会长期保留。
如果要用 Actions，必须额外把 qdc.duckdb、raw、parquet 和 qlib 输出写回对象存储，复杂度反而更高。
```

云服务器选型原则：

```text
优先选择网络到 cninfo、sse、eastmoney、sina 稳定的区域。
先用最低规格跑一周 smoke，再决定是否升级 CPU、内存和磁盘。
控制台只绑定 127.0.0.1，通过 SSH tunnel 访问，不直接暴露公网端口。
凭据放服务器环境变量或密钥文件，不写入 git、Markdown 或配置样例。
```

## 7. P0 优先级

P0-A：Qlib provider 依赖检查口径。

```text
明确配置项或文档约定的 provider_uri。
检查 day.txt 最新日期是否到最近完整交易日。
抽样确认 $close / $volume / $factor 可读。
如果基础 provider 过旧，QDC 当日 external factor 仍可采集，但不声明训练底座可用。
已落地：`qlib_provider.provider_uri` 默认指向 `~/.qlib/qlib_data/cn_data`；`qdc verify-qlib` 检查 day.txt、close/volume/factor 文件并通过 Qlib 抽样读取；控制台展示文件级状态。
```

P0-B：公告 metadata 主链路。

```text
CNINFO metadata 每日增量稳定。
SSE 作为补源观察。
PDF 下载默认关闭，按需要打开。
公告标题、发布时间、URL、instrument 映射和 raw_object 可追溯。
已落地：`crawl-daily` / `crawl-run` 默认 metadata-only；需要 PDF 时显式传 `--download-pdfs`。
```

P0-C：新闻源收敛。

```text
保留 1 到 2 个默认新闻补位源。
统计空结果率、解析失败率、重复率和映射率。
NBD 若继续不稳定，默认退出每日源，只保留手动 smoke。
已落地：默认新闻源收敛为 `sina_finance_news` 和 `eastmoney_roll_news`；crawler result 和 document bundle manifest 记录 empty_result_rate、duplicate_rate、parse_failed_rate、mapping_rate。
```

P0-D：外部因子输出。

```text
daily_news_factor / daily_announcement_factor 可重算。
因子按 publish_date 和交易日历对齐。
因子字段命名和 Qlib external handler 对齐。
已落地：`build-factors --factor-set all` 重算两张因子表；字段与 `QdcAlpha158WithExternal.DEFAULT_EXTERNAL_FIELDS` 对齐；`verify-qlib` 默认检查基础 `$close/$volume/$factor`。
```

## 8. P1/P2 扩展方向

P1：研报。

```text
优先接 metadata 和标题摘要。
保存 publish_time、机构、分析师、股票映射、URL、PDF hash。
先做研报数量、评级方向、风险提示和主题词因子。
```

P1：互动问答和投资者关系。

```text
优先公开、可追溯、无需登录的来源。
保留问题、回复、回复时间、公司、主题和情绪。
构建关注度、回复延迟、风险主题和新业务主题因子。
```

P2：公开舆情。

```text
只采公开合法内容。
不绕过登录、验证码或付费墙。
先做标题/摘要/热度 metadata，不保存敏感个人信息。
```

P2：法律处罚、招投标、招聘、专利。

```text
按行业相关性选择 1 类做最小可验证增量。
每次只新增一类来源，并补齐 raw、silver、factor、quality 和控制台预览。
```

## 9. 控制台口径调整

控制台仍可展示已有结构化表，但每日结论应改为：

```text
Qlib 基础 provider 状态
公告采集状态
新闻采集状态
外部因子构建状态
质量和异常源
```

旧的“日线行情、复权因子、涨跌停三项核心数据覆盖全部应采标的”不再作为 QDC 每日可用性的核心结论。基础行情可用性应来自 Qlib provider 检查。

## 10. 冻结和降级项

冻结：

```text
历史回补底座补齐
全 A 结构化每日采集
run-backfill 队列消费
回补控制台主入口
用 AkShare 免费新闻源做历史训练结论
```

降级为诊断：

```text
daily-pipeline
AkShare daily_bar / adj_factor / price_limit
Eastmoney 结构化备源
Sina realtime 结构化 fallback
```

## 11. 验收标准

近期验收不再要求全 A 基础行情由 QDC 采完，而是要求：

```text
Qlib provider 可用性检查口径清楚。
CNINFO 公告 metadata 单日可稳定入库。
至少一个新闻补位源单日可稳定入库。
daily_announcement_factor 和 daily_news_factor 可重算。
外部因子字段能被 Qlib handler 追加读取。
控制台不再误导用户去跑全 A 结构化采集。
```
