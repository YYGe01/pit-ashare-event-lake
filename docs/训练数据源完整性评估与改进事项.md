# 训练数据源完整性评估与改进事项

> 评估日期：2026-05-12
> 评估目标：判断当前 `quant_data_center` 采集资产是否足够支撑 Qlib 训练，并沉淀后续数据源和工程改进事项。

## 1. 总体结论

当前数据链路已经足够验证 QDC 到 Qlib 的数据层闭环，包括回补、清洗、日频因子、Parquet 同步、Qlib provider 导出和 Qlib 读取验证。

但当前数据还不够支撑严肃的模型训练结论，主要原因是：

- 历史回补范围仍偏短，当前主要真实训练样本集中在 `2023-01-01` 到 `2024-12-31`。
- `2025` 数据不是上游缺失，而是当前项目尚未把主要训练集继续回补和导出到 `2025-12-31` 或最近完整交易日。
- 当前 universe 主要使用最新 CSI300 快照向历史回填，存在幸存者偏差，需要历史成分或全 A PIT 股票池。
- 新闻当前只能作为近实时补位源，不适合作为完整历史新闻训练集。
- 公告比新闻更可靠，但当前仍是标题和 URL 级别，后续需要官方公告源、PDF 原文、hash、披露时间和跨源校验。

因此后续应先把纯行情 Qlib baseline 做扎实，再把公告因子纳入正式对比实验，新闻因子应等授权历史源接入后再做训练结论。

## 2. 当前采集范围

当前真实回补只支持 `source_id=akshare` 或 `akshare*`。

| dataset | 当前接口或逻辑 | 训练可用性判断 | 主要缺口 |
| --- | --- | --- | --- |
| `stock_basic` | `stock_info_a_code_name` | 可做基础标的名录 | 缺上市日、退市日、ST 状态、历史证券简称等 PIT 字段 |
| `universe_constituent` | `index_stock_cons_csindex` | 可做当前快照 universe | 缺历史成分变更，历史训练存在幸存者偏差 |
| `trade_calendar` | `tool_trade_date_hist_sina` | 基础可用 | 需要持续校验未来日期和特殊休市 |
| `daily_bar` | `stock_zh_a_daily` | 可支撑 Alpha158 基础特征 | 需要补齐长历史和完整 universe |
| `adj_factor` | 未复权和前复权 `stock_zh_a_daily` 推导 | 可用于 smoke 和基础导出 | 严格 PIT 复权需要分红送配和除权日驱动 |
| `price_limit` | 前收盘和板块规则推导 | 可做基础涨跌停字段 | ST、新股首日、复牌首日、北交所等细则不足 |
| `trade_status` | `stock_tfp_em` | 可记录部分停牌状态 | 需要形成交易日 x 标的的完整状态面 |
| `announcement` | `stock_notice_report(symbol="全部", date=...)` | 可做标题级公告 count 和事件因子 | 需要官方源、正文/PDF、准确披露时间、公告类型标准化 |
| `news` | `stock_news_em` + 全局快讯 fallback | 只适合近实时补位 | 不适合作为完整历史新闻库 |

## 3. 日期范围和样本事实

当前文档和 smoke 记录中，主要 Qlib 训练样本范围是：

```text
2023-01-01 -> 2024-12-31
```

真实记录：

```text
daily_bar: 299 个左右 CSI300 标的，484 个交易日，143859 行
Qlib export: 299 instruments, 484 calendar dates
news: 2023-2024 历史区间基本为空
```

2026-05-12 抽样验证：

```text
AkShare version: 1.18.60
标的：SH600000, SZ000001
区间：2025-01-01 -> 2025-12-31
结果：两只标的各 243 行，首日 2025-01-02，末日 2025-12-31
```

这说明 `2025` 行情数据上游可取，当前缺口来自项目尚未执行对应回补、同步和 Qlib 导出。

近期交易日抽样：

```text
区间：2026-05-01 -> 2026-05-11
交易日：2026-05-06, 2026-05-07, 2026-05-08, 2026-05-11
```

后续正式训练建议优先使用最近完整交易日作为上限。例如在 2026-05-12 白天评估时，上限应先取 `2026-05-11`，避免当日未收盘数据进入训练。

## 4. Qlib 训练前最低要求

正式做 Alpha158 或外部因子对比前，至少应补齐：

```text
daily_bar      2015-01-01 -> 最近完整交易日
adj_factor     2015-01-01 -> 最近完整交易日
price_limit    2015-01-01 -> 最近完整交易日
trade_calendar 2015-01-01 -> 最近完整交易日
stock_basic    覆盖研究期内上市、退市和活跃状态
universe       历史 CSI300 成分或全 A PIT 股票池
```

训练前必须输出覆盖报告：

- 每年、每月、每个 dataset 的行数。
- 每个标的的交易日覆盖率。
- `daily_bar` 与 `trade_calendar` 的缺失矩阵。
- `adj_factor`、`price_limit` 相对 `daily_bar` 的覆盖率。
- 导出到 Qlib 后的 instruments 数、calendar 数、feature 行数。
- Alpha158 warmup 后 label 非空率。

建议训练切分时保留足够 warmup 区间。例如 Alpha158 这类 rolling 特征至少保留 60 到 120 个交易日的训练前置窗口，避免特征前段大量空值影响判断。

## 5. 新闻和公告完整性判断

### 公告

当前公告采集按日期取全市场公告，再按股票代码落库。抽样显示 `stock_notice_report` 能拿到对应日期的全市场公告，并能命中 `SH600000`、`SZ000001` 的公告。

但当前公告仍不能视为最全，原因是：

- 当前依赖 AkShare 封装接口，不是项目直接接官方披露平台。
- 当前主要保留标题、日期、URL，缺 PDF 原文和正文抽取。
- 当前字段没有稳定区分披露时间、抓取时间、公告类型、公告修订版。
- 缺跨源校验，无法判断某天公告是否漏采。

更完整的公告方案：

- 主源：巨潮资讯 CNINFO。
- 补源：上交所、深交所、北交所公告查询。
- 授权源：Tushare `anns_d`，适合作为工程化补充，但需要单独权限。

公告入库应补充字段：

```text
source_publish_time
observed_at
exchange
announcement_category
announcement_subtype
pdf_url
pdf_sha256
html_url
body_text_path
is_correction
related_announcement_id
source_record_id
```

### 新闻

当前新闻不够训练使用。`stock_news_em` 实测每个标的通常只返回最近少量新闻，历史追溯能力不足；全局快讯 fallback 只能按股票代码、内部标的代码和证券简称做匹配，存在漏召回和误匹配。

因此当前新闻因子只能用于链路验证和近实时补位，不能用于判断新闻 alpha 是否有效。

更完整的新闻方案：

- 短期保留 AkShare 免费新闻源，只作为补位和 smoke 数据。
- 中期接入一个授权历史新闻源，至少覆盖 6 年以上历史，支持标题、正文、发布时间、来源、URL 和股票映射。
- 长期用两个以上来源做交叉校验和去重，避免单源缺失或上游规则变更。

候选源：

| 类型 | 候选 | 适用性 |
| --- | --- | --- |
| 免费公开源 | AkShare 东方财富个股新闻、财联社/同花顺/东方财富/新浪/富途全局快讯 | 近实时补位，不适合完整历史 |
| 授权数据源 | Tushare 资讯、聚宽 JQData、财联社授权接口 | 适合个人研究历史新闻 |
| 机构级数据源 | Wind、Choice、同花顺 iFinD、CSMAR、RESSET | 适合生产级历史新闻和公告审计 |

## 6. 优先级改进事项

### P0：先补齐行情训练底座

- 回补 CSI300 或全 A 的 `2015-01-01 -> 2026-05-11` 日线、复权、涨跌停和交易日历。
- 把 `2025` 和 `2026` 最近完整交易日纳入 Qlib 导出。
- 增加训练前 coverage 报告命令或质量规则。
- 跑纯 Alpha158 baseline，先不依赖新闻因子。
- 明确训练、验证、测试切分，避免只用 2023-2024 的短样本做结论。

### P1：解决 universe 和 PIT 风险

- 接历史 CSI300 成分变更，或建立全 A PIT 股票池。
- 补 `stock_basic` 的上市日、退市日、ST 状态和证券简称变更。
- 明确停牌、退市、新股上市初期的样本处理策略。
- 将 `price_limit` 从简化规则升级为更接近交易所规则的实现。

### P2：公告进入正式因子

- 接 CNINFO 或交易所官方公告源。
- 保存 PDF 原文、hash、标题、公告类型、披露时间和抓取时间。
- 对同一公告的多个来源做去重和差异记录。
- 基于公告类型和标题事件规则重建 `daily_announcement_factor`。
- 在 Qlib 中做纯行情 baseline 与行情加公告因子的对比实验。

### P3：新闻进入正式因子

- 选择一个授权历史新闻源作为主源。
- 保存标题、正文、发布时间、来源、URL、正文 hash 和证券映射依据。
- 做跨源去重、简称歧义处理和新闻到交易日的严格对齐。
- 重建 `daily_news_factor` 后，再进入 Qlib 对比实验。

## 7. 阶段验收标准

行情底座验收：

```text
2015-01-01 -> 最近完整交易日
目标 universe 覆盖率明确
daily_bar / adj_factor / price_limit 覆盖率可解释
Qlib provider 可读取
Alpha158 baseline 可稳定运行
```

公告底座验收：

```text
公告主源可按日期增量和历史回补
PDF 或正文可追溯
公告去重稳定
公告因子可重算
公告因子进入 Qlib 后有独立实验记录
```

新闻底座验收：

```text
授权历史源覆盖训练期
新闻到证券的映射规则可审计
新闻发布时间和交易日对齐清晰
新闻因子不再大面积为 0
新闻因子进入 Qlib 后有独立实验记录
```

## 8. 当前推荐执行顺序

```text
1. 补齐 2015-01-01 -> 2026-05-11 的基础行情和 Qlib 导出。
2. 增加 coverage 报告，确认 2025 和 2026 数据已进入 provider。
3. 跑纯 Alpha158 baseline。
4. 接官方公告源，重建公告因子并做对比实验。
5. 评估并接入授权历史新闻源。
6. 重建新闻因子，再做新闻 alpha 对比。
```

不要在新闻历史源未稳定前，用当前免费新闻源的结果判断新闻因子无效。
