# 每日非结构化采集与 Qlib 外部因子实施计划

> 创建日期：2026-05-12
> 重写日期：2026-05-14
> 当前定位：这是 QDC 当前每日采集状态和下一步的唯一入口。结构化基础行情由 Qlib `cn_data` 维护，QDC 默认聚焦公告、新闻、研报、舆情等非结构化数据和 external factors。

## 1. 一句话结论

当前项目主线已经调整为：

```text
Qlib / 社区 cn_data / Qlib 增量脚本
  -> 维护基础行情、复权因子、交易日历和 instruments

QDC
  -> 采集非结构化数据
  -> 归一化为 announcement / news / 后续 research_report / sentiment 等表
  -> 构建 daily external factors
  -> 对齐到 Qlib provider_uri
```

因此，QDC 不再以“全 A 日线、复权、涨跌停每日采集”为默认目标。既有 `daily-pipeline` 和 AkShare 结构化 collector 保留为历史能力、smoke、诊断和应急补数，不再作为 P0 主线。

当前默认入口：

```text
qdc crawl-daily       非结构化文档每日采集
qdc build-factors     文本事件日频因子
qdc sync-parquet      DuckDB 到 Parquet 同步
qdc quality           基础质量检查
qdc console           本地观察面
```

## 4. 当前默认数据源边界

实体映射基准：

```text
公告、新闻、研报和舆情等文档源的股票实体映射以 qdc_silver.stock_basic 为准。
Qlib provider 的 instruments/all.txt 只用于基础行情健康检查和 Qlib 读取验证，不作为文档采集默认股票池。
stock_basic 为空时，标题里即使出现股票简称也无法稳定映射到 instrument；当前 `crawl-run` / `crawl-daily` 会在新闻采集前自动用 AkShare 初始化该映射基准。
```

### 公告

| source_id | 当前定位 | 默认策略 |
| --- | --- | --- |
| `cninfo_announcement` | 公告主源 | 默认采 metadata；PDF 下载按需开启 |
| `sse_announcement` | 上交所公告补源 | 默认可跳过 PDF 下载 |
| SZSE / BSE | 候选 | 确认稳定日期字段后再接入 |

公告硬规则：

```text
必须保留 publish_time / publish_date / collect_time。
publish_date 来自来源披露时间，不用 collect_time 伪造。
PDF 原文保存必须记录 hash、size、object_id 和下载状态。
默认不把 PDF 下载作为每日 P0，先稳定 metadata 和事件因子。
```

### 新闻

| source_id | 当前定位 | 风险 |
| --- | --- | --- |
| `eastmoney_roll_news` | 当日滚动新闻补位 | 适合近实时，不适合历史主源 |
| `sina_finance_news` | 近实时补位 | 隔天历史日期可靠性有限 |
| `nbd_company_news` | 手动 smoke 源 | 本地记录出现 SSL/502 失败，已退出默认每日源 |
| 厂商级 opt-in 源 | 覆盖观察和补位 | 不作为训练级历史新闻结论 |

新闻硬规则：

```text
必须解析明确 YYYY-MM-DD HH:MM[:SS]。
无法确认发布日期的记录不进入 silver。
当前免费新闻源不用于判断新闻 alpha 是否有效。
正式训练需要授权历史新闻源或可长期稳定追溯的公开源。
```

已标记的待清洗风险：

```text
A 股公司简称可能是通用名词，例如“机器人”既可能指 SZ300024 机器人，也可能只是普通语义里的机器人。
当前新闻采集先保留 raw / bronze / 现有 silver 结果，不立即重算历史数据。
后续做新闻清洗、情绪分类、事件因子正式训练前，必须先补新闻到标的的归因置信度标记。
```

后续建议给 `qdc_silver.news` 或独立新闻归因表补充字段：

```text
entity_match_method        source_stock_tag / stock_code / full_name / short_name / short_name_with_context
entity_match_confidence    high / medium / low
entity_match_reason        命中来源标签、股票代码、公司全称、简称、正文证券上下文等可解释原因
ambiguous_entity_flag      是否命中“机器人”这类通用简称或多义简称
requires_entity_review     低置信或多义命中是否需要清洗复核
company_news_eligible      是否允许进入公司级 news_count、情绪因子和事件因子
```

清洗口径：

```text
来源自带股票标签、股票代码或公司全称命中，可视为高置信。
通用简称单独命中只作为候选，不应直接进入公司级因子。
通用简称如果同时出现股票代码、公司全称、证券语境或来源结构化标签，才可提升置信度。
低置信新闻可保留为行业/主题新闻或 unlinked/ambiguous 记录，但不应计入该公司的 news_count 和 sentiment。
```

东方财富滚动新闻降级规则：

```text
每日主链路优先保证标题、发布时间、URL、source_record_id 和 instrument 映射入库。
正文预览不是 P0，不允许拖慢整源采集；默认与 PDF 一样先跳过正文。
当前 eastmoney_roll_news 每日采集不抓正文页，只保留 metadata。
记录保留 metadata，body_download_status 标记为 skipped_metadata_only。
后续若需要正文内容，另做低优先级 body enrichment / URL 正文补采任务，按限速、短超时和可恢复队列慢慢补。
列表页单次请求最多等待 10 秒；列表翻页间隔按 0.5 秒执行，避免目标日页数较多时拖到十几分钟。
标题到 instrument 映射使用预构建股票索引，避免每条新闻循环全市场股票做正则匹配。
```

### 非结构化日期扫描算法

非结构化源按日期口径分两类处理，后续新增研报、舆情、互动问答等源也默认套用这个判断框架。

第一类是来源支持精确日期查询的源，例如 `cninfo_announcement` 和 `sse_announcement`：

```text
请求参数必须显式传目标日期 D。
如果来源返回总页数，默认翻完所有页。
只有显式 smoke / 调试时才传 --max-pages。
如果 --max-pages 小于来源总页数，manifest 必须记录 date_scan_complete=false 和 date_scan_stop_reason=max_pages。
silver 只接受来源日期字段等于 D 的记录。
```

第二类是倒序滚动列表源，例如 `eastmoney_roll_news` 和 `sina_finance_news`：

```text
目标日期 D 的时间窗为 [D 00:00:00, D+1 00:00:00)。
默认使用快速定位扫描，而不是从最新页线性扫到目标日。
先抓第 1 页；如果整页都晚于 D，则按 2、4、8、16... 指数探测。
找到第一个不再整页晚于 D 的页后，在相邻探测区间内二分定位边界页。
从边界页向前回看 2 页，再顺序扫描目标日窗口，防止滚动页轻微乱序。
publish_time >= D+1 的记录判为 newer，只进 raw/bronze，不进 silver。
D <= publish_time < D+1 的记录判为 target，才进入映射、document records、silver 和因子。
publish_time < D 的记录判为 older。
一旦已经命中过 target，并连续看到 2 个整页 older，再停止，防止页面轻微乱序。
如果第一页或扫描过程中已经整页早于 D 且从未命中过 target，认为目标日无可用记录并停止。
默认不传 --max-pages，由 hard_max_pages 防止无限翻页；当前 hard_max_pages=200。
如果打到 --max-pages / hard_max_pages / source_timeout，manifest 必须记录 date_scan_complete=false。
```

滚动源 manifest 必须保留这些排障字段：

```text
date_scan_strategy
target_date / target_start / target_end_exclusive
date_scan_complete
date_scan_stop_reason
date_scan_pages_scanned
date_scan_fetch_strategy
date_scan_probe_pages
date_scan_sequential_start_page
date_scan_first_target_page / date_scan_last_target_page
scanned_provider_record_count
provider_record_count
newer_skipped_count
target_provider_record_count
older_seen_count
unknown_date_count
instrument_dictionary_count
mapping_failure_reason
```

注意：`provider_record_count` 表示目标日期 D 的 provider 记录数；`scanned_provider_record_count` 表示为找到目标日期而实际翻页看到的总记录数。这样可以区分“源里有新闻但不是目标日”和“目标日有新闻但映射失败”。

### 代理策略

本地 QDC 默认不读取 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、`NO_PROXY` 及对应小写环境变量。原因是本地实测中不稳定主要来自环境变量代理，表现为交易所和新闻源超时、断连或返回不一致。默认配置为：

```yaml
runtime:
  use_environment_proxy: false
```

如确实需要走公司网络代理或专用代理，可显式改成 `true`，但应优先固定一个可靠出口，而不是代理池。代理池会引入 IP 质量、封禁、页面差异、合规和排障复杂度。

### 研报、舆情和其他另类事件源

P1-A 研报、P1-B 互动问答已按 metadata-first 落地。后续新增源按“训练可用性、可追溯性、覆盖率、合规风险、工程成本”排序；每次只新增一类来源，并补齐 raw、silver、factor、quality 和控制台预览。

新闻和公开舆情必须分表处理：

```text
news
  财经媒体、资讯站和滚动新闻列表的标题 / 发布时间 / URL / 来源 metadata。
  当前已落 qdc_silver.news 和 daily_news_factor。
  重点回答“媒体报道了什么”。

public_sentiment
  公开讨论、热度、话题和平台互动 metadata。
  不写入 qdc_silver.news，已单独落 qdc_silver.public_sentiment。
  重点回答“市场公开讨论什么、关注度和情绪如何变化”。
```

候选源的训练口径：

```text
研报 metadata / 标题摘要
公开舆情 metadata
交易所监管问询 / 处罚 / 诉讼 / 执行
招投标 / 政府采购
专利 / 商标 / 软著
招聘 JD
```

这些数据不是每个标的每天都有。缺失不能简单当成坏数据；因子默认做 rolling 7/30/90 日窗口、coverage flag 和事件强度，而不是要求全市场逐日全覆盖。

## 6. 日频预测和调仓采集参考

适用场景：Qlib 日频策略，一天预测一次，一天调仓一次。QDC 的每日采集调度应服务这个可见性口径，而不是把某一次盘后快照直接当最终训练数据。

当前默认定时结论：

```text
默认把“次日凌晨采前一自然日”作为 final 封账口径。

例如：
2026-05-14 18:00 采 2026-05-14，只能算截至 18:00 可见的 provisional 版本。
2026-05-15 凌晨或早晨再采 2026-05-14，才作为 2026-05-14 的 final 候选版本。

如果只保留一次定时任务，优先选择 T 日凌晨/早晨采 T-1，而不是 T-1 当天傍晚采 T-1。
如果需要 T 日开盘前预测，默认使用 T 07:30 采 T-1 并封账。
如果不做开盘前预测，只做离线研究，T 01:00-03:00 采 T-1 也可以作为低成本默认。
```

当前实现注意事项：

```text
默认 crawl-daily 对同一 source_id、dataset、crawl_date 和 parser request 成功任务会跳过。
crawl-daily 会自动重跑同日 failed 任务；需要重跑已 success 任务时显式传 --force。
最小稳定方案是只在 T 日凌晨/早晨采 T-1，把这次采集作为该自然日的 final。
若未来需要盘后 preview + 次日 final 两版，优先使用 --force 或独立 final 任务机制，避免把 provisional 误当成最终封账。
```

推荐默认节奏：

```text
T-1 15:00        A 股收盘。
T-1 15:45        当日初扫，采 T-1 公告和新闻，生成 provisional 因子。
T-1 18:30        晚间补扫，覆盖一批盘后公告和新闻。
T-1 22:30        夜间补扫，覆盖多数晚间披露，作为次日预测前的主要候选版本。
T 07:30          最终补扫 T-1，并扫描隔夜到开盘前事件，生成 final 候选版本。
T 08:20          build-factors、sync-parquet、quality，确认 Qlib provider 新鲜度。
T 08:30-08:50    用 T-1 及以前可见数据预测 T 日收益，生成目标持仓。
T 09:35-10:00    开盘后避开最初几分钟冲击，执行日频调仓。
```

最小可行定时：

```text
T-1 22:30        采 T-1，当作夜间 provisional 版本。
T 07:30          重采 T-1 并封账，补齐 22:30 之后到预测 cutoff 前观察到的数据。
```

可见性硬规则：

```text
因子日期归属仍使用 publish_date。
是否能用于某次预测必须看 observed_at / collect_time / asof cutoff。
T-1 18:00 采到的数据只能算 provisional，不能视作最终完整版本。
T 07:30 之后、预测 cutoff 之后才观察到的数据，不进入 T 日开盘前预测特征。
T 日收盘后发布或采集的数据，不能用于预测 T 日收益，只能用于 T+1 或之后。
回测、训练、实盘预测必须使用同一个 cutoff 口径，否则容易引入未来函数。
```

采集版本建议：

```text
raw 继续追加保存每次观察证据。
silver 按 source_id、URL、发布时间、标题 hash 或正文 hash 做幂等去重。
gold external factors 应能区分 provisional / final，或至少记录 factor_run 的 asof_cutoff。
每日 07:30 任务负责封账最近完整交易日，周末和节假日可每天扫描最近 3 个自然日防迟到披露。
```

### 云端自动运行建议

本项目当前采用 DuckDB 本地文件、raw 文件包、Parquet 和 Qlib provider 目录，最小改造的云端方案不是先上云数据库，而是先把“笔记本本地运行”迁移成“云服务器常驻运行”。

推荐第一阶段：

```text
一台小型云服务器/VPS
  -> 安装 conda 和 ai-trader 环境
  -> 拉取本仓库
  -> data/quant_data_center 放在云服务器数据盘
  -> cron 或 systemd timer 每天按 Asia/Shanghai 时间运行采集脚本
  -> 任务完成后把 raw、parquet、qlib 和 qdc.duckdb 备份到对象存储或网盘
  -> 笔记本只负责远程查看、拉取结果和本地分析，不再负责定时开机
```

默认定时脚本口径：

```text
计算 target_date = 今天 - 1 天。
qdc crawl-daily --date <target_date>
qdc build-factors --factor-set all --start <target_date> --end <target_date>
qdc sync-parquet --layer all
qdc quality --start <target_date> --end <target_date>
```

云端存储建议：

```text
短期：DuckDB 继续放在云服务器本地数据盘，raw/parquet/qlib 文件也放本地盘。
备份：每天采集结束后复制到对象存储，例如 S3/OSS/COS/R2，或用 rclone 同步到云盘。
同步到笔记本：从对象存储或云盘拉取 data/quant_data_center 的备份副本。
```

不建议第一阶段直接改云数据库：

```text
当前代码读写的是本地 DuckDB 文件和本地文件目录。
PostgreSQL/RDS 这类云数据库不能直接替代 raw 文件、Parquet 和 Qlib provider。
如果要上云数据库，需要先重构 storage/database.py，并把 raw/parquet 另放对象存储。
```

不建议把 GitHub Actions 作为主采集运行环境：

```text
Actions 的定时适合 CI 或短任务 smoke，不适合作为训练数据主采集底座。
runner 是临时环境，本地 DuckDB 和 raw 文件默认不会长期保留。
如果要用 Actions，必须额外把 qdc.duckdb、raw、parquet 和 qlib 输出写回对象存储，复杂度反而更高。
```

云服务器选型原则：

```text
优先选择网络到 cninfo、sse、eastmoney、sina 稳定的区域。
先用最低规格跑一周 smoke，再决定是否升级 CPU、内存和磁盘。
控制台只绑定 127.0.0.1，通过 SSH tunnel 访问，不直接暴露公网端口。
凭据放服务器环境变量或密钥文件，不写入 git、Markdown 或配置样例。
```

## 7. 待修复事项

新闻到标的归因清洗。

```text
性质：待修复 / 后处理事项，不是当前新增采集源任务。
时机：等新闻、研报、互动问答和后续文本数据采集稳定后，统一做实体归因后处理。
目标：避免通用简称、多义简称和低置信标题命中污染公司级因子。
```

后处理要求：

```text
为新闻归因增加置信度、命中方法、命中原因和多义简称标记。
建立通用简称/多义简称 deny-list 或弱 alias 列表，首个已知样例为“机器人”。
在情绪分类和正式 daily_news_factor 训练前，先排除 low confidence / ambiguous 的公司级归因。
质量检查新增“单公司新闻数异常且主要由简称命中贡献”的提示。
```

理由：这是当前已入库新闻因子进入训练前的必要清洗，不新增来源，但会直接影响 `news_count`、情绪和风险主题因子的可信度。

## 8. 扩展源优先级

P1-A：研报。已完成 metadata-first 版本。

```text
已接入 eastmoney_research_report。
保存 publish_time、机构、分析师、股票映射、URL、PDF URL 和 metadata 原始证据；默认不下载 PDF。
已落 qdc_silver.research_report。
已落 daily_research_report_factor：research_report_count、research_institution_count、research_analyst_count、rating 方向计数、research_risk_count、research_topic_strength 和 research_sentiment_mean。
控制台每日数据宽表已显示 research_report_count；和新闻、公告一样只显示数量，点击数量可查看研报标题、机构、分析师、评级、来源 URL 和本地 metadata。
```

后续：如需 PDF hash，单独增加低优先级 PDF 下载 / enrichment 队列，不阻塞每日默认采集。

P1-B：互动问答和投资者关系。已完成 metadata-first 版本。

```text
已接入 cninfo_investor_interaction。
保存 publish_time、question_time、answer_time、公司、问题、回复、回复状态、回复延迟、主题标签、情绪分和 metadata 原始证据。
已落 qdc_silver.investor_interaction。
已落 daily_investor_interaction_factor：question_count、reply_count、reply_delay_hours_mean、risk_topic_count、new_business_topic_count 和 sentiment_mean。
控制台每日数据宽表已显示 investor_interaction_count；和新闻、公告、研报一样只显示数量，点击数量可查看问题、回复状态、回复时间、回复延迟、主题、来源 URL 和本地 metadata。
```

口径：互动易按回复/更新时间筛目标日；已回复问答的 `publish_time` 用回复时间或更新时间，未回复问答回退到提问时间，同时保留原始 `question_time`。理由是回复出现时才形成公司回应类可观测事件。

P2-A：公开舆情。已完成 metadata-first 版本。

```text
已接入 eastmoney_public_sentiment。
只采公开合法内容；不绕过登录、验证码或付费墙。
保存交易日、instrument、股票名称、关注指数、排名、综合得分、排名变化和热门关键词 metadata。
不保存帖子正文、用户昵称、用户主页、评论正文或其他敏感个人信息。
已单独落 qdc_silver.public_sentiment，不混入 qdc_silver.news。
已落 daily_public_sentiment_factor：public_sentiment_count、public_sentiment_heat_mean、public_sentiment_rank_best、public_sentiment_keyword_count、public_sentiment_risk_topic_count、public_sentiment_new_business_topic_count 和 public_sentiment_sentiment_mean。
控制台每日数据宽表已显示 public_sentiment_count；点击数量可查看标题、平台、热度排名、热度分、关键词、来源 URL 和本地 metadata。
```

理由：公开舆情能补充市场关注度，但噪声、重复转载、平台合规和实体归因风险更高；必须 metadata-only 起步。

P2-B：交易所监管问询、法律处罚、诉讼和执行。

```text
优先选公开权威来源。
保留事件时间、主体、处罚/问询类型、金额或处分级别、URL、文号和股票映射。
先做 penalty_or_regulatory_flag、risk_event_count、severity_score 和近 30/90 日风险事件强度。
```

理由：覆盖稀疏，但风险含义强、可追溯性好，适合做风控和负面事件过滤；优先级高于行业特定的招投标、专利和招聘。

P2-C：招投标 / 政府采购。

```text
适合建筑、软件、环保、医疗设备、军工等 ToB 或项目制行业。
保留公告时间、项目名、金额、甲方、地区、URL、公司映射和中标/招标状态。
先做 tender_count、award_amount_sum、industry_project_topic_count。
```

理由：对部分行业可能很有价值，但不是全市场通用信号，应在行业样本上做最小可验证增量。

P2-D：专利 / 商标 / 软著。

```text
适合科技、医药、制造、新能源等研发驱动行业。
保留申请/授权时间、专利名、申请人、IPC/CPC 分类、URL、公开号和公司映射。
先做 patent_count、grant_count、tech_topic_count 和研发方向主题因子。
```

理由：更偏中长期创新信号，事件滞后较大，适合行业化研究，不应优先于研报、互动问答和监管风险事件。

P2-E：招聘 JD。

```text
只采公开合法的岗位 metadata，不保存个人信息。
保留发布时间、岗位、城市、职能、技能关键词、URL 和公司映射。
先做 hiring_count、new_business_skill_count、region_expansion_count。
```

理由：能观察扩张方向和新业务布局，但平台条款、去重、岗位重复发布和公司主体映射难度较高，当前排在最后。

## 9. 控制台口径调整

控制台仍可展示已有结构化表，但每日结论应改为：

```text
Qlib 基础 provider 状态
公告采集状态
新闻采集状态
外部因子构建状态
质量和异常源
```

旧的“日线行情、复权因子、涨跌停三项核心数据覆盖全部应采标的”不再作为 QDC 每日可用性的核心结论。基础行情可用性应来自 Qlib provider 检查。
