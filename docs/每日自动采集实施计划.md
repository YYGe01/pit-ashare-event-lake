# 每日自动采集实施计划

> 创建日期：2026-05-12
> 目标：在不依赖历史回补已完成的前提下，每天收盘后自动采集全 A 日频数据，长期累积可供 Qlib 训练使用的数据底座。

## 1. 结论

当前采用 `ai-trader` conda 环境作为 QDC 运行环境：

```powershell
conda run -n ai-trader python -m pip install -e ".[market,dev]"
conda run -n ai-trader qdc validate-config
```

每日自动采集第一版使用新增命令：

```powershell
conda run -n ai-trader qdc daily-pipeline
```

默认行为：

```text
运行日期：当天，使用 config 中的 Asia/Shanghai 时区
股票范围：all_a，全 A 当前 active 标的
数据源：AkShare
采集频率：日频，建议每个交易日 18:30 后运行
输出：raw JSON、bronze Parquet、qdc_silver、gold Parquet、Qlib provider
```

`daily-pipeline` 不新建第二套采集逻辑，而是复用当前 `daily` / `run-backfill` 的 writer：

```text
stock_basic 刷新
  -> 解析 all_a 全市场标的
  -> daily 单日任务规划和执行
  -> build-factors
  -> sync-parquet
  -> quality
  -> export-qlib
```

## 2. 为什么按收盘后 18:30 跑

A 股日线行情、涨跌停和复权数据在收盘后才更稳定。当前 QDC 目标是服务 Qlib 日频训练，不做盘中交易，因此第一版不需要分钟级或流式采集。

建议时间：

```text
交易日 18:30 Asia/Shanghai
```

原因：

```text
避免当日未收盘数据进入训练
给上游 AkShare / 东方财富 / 新浪等免费源留出更新延迟
Windows 计划任务配置简单，可每日固定运行；节假日空跑可接受
```

如果后续发现 18:30 仍有上游延迟，可调整到 20:30 或次日 06:30。

## 3. 当前覆盖范围

每日采集覆盖这些 dataset：

```text
stock_basic      全 A 标的快照，用于解析 all_a
trade_calendar   交易日历
daily_bar        日线行情
adj_factor       复权因子
price_limit      涨跌停价格
trade_status     停复牌状态
announcement     公告标题
news             新闻标题和全局快讯 fallback
```

其中需要按标的分批的 dataset：

```text
daily_bar
adj_factor
price_limit
news
```

公告当前按日期拉全市场，再按股票代码入库；不需要逐标的请求。

## 4. 数据源现状和非结构化数据判断

当前真实采集源仍然只有 AkShare：

```text
source_id = akshare
```

暂未实现：

```text
Tushare
JQData
Wind / Choice / iFinD
CNINFO 官方公告源
交易所官方公告源
社交媒体 / 股吧 / 论坛舆情源
```

对 Qlib 训练的判断：

```text
行情、复权、涨跌停、停牌等结构化日频数据：
  可先作为免费源底座，每天收盘后持续积累，并用 quality / coverage 报告控制风险。

公告：
  当前是 AkShare stock_notice_report 的标题和 URL 级别数据。
  可做公告 count、标题事件规则和训练链路 smoke。
  但还不够做严肃公告 NLP 或可审计事件研究。

新闻：
  当前是 stock_news_em 加全局快讯 fallback。
  适合近实时补位和每日积累。
  不适合作为完整历史新闻训练集，也不能据此判断新闻 alpha 是否有效。

舆情：
  当前没有真正的社交舆情源。
```

非结构化数据正式进入训练前，至少需要补齐：

```text
准确发布时间 / 披露时间
采集时间 observed_at
正文或 PDF 原文
原文 hash
来源和 URL
证券映射依据
跨源去重
修订版 / 更正公告关系
公告类型或新闻主题标签
```

## 5. 常用命令

初始化和环境验证：

```powershell
conda run -n ai-trader qdc validate-config
conda run -n ai-trader qdc init
conda run -n ai-trader qdc db-info
```

小范围控制面 smoke，不访问真实日线接口：

```powershell
conda run -n ai-trader qdc daily-pipeline --date 2026-05-11 --symbols "SH600000,SZ000001" --batch-size 1 --control-only
```

小范围真实 smoke：

```powershell
conda run -n ai-trader qdc daily-pipeline --date 2026-05-11 --symbols "SH600000,SZ000001" --batch-size 1
```

全市场计划预览：

```powershell
conda run -n ai-trader qdc daily-pipeline --date 2026-05-11 --plan-only
```

全市场正式每日运行：

```powershell
conda run -n ai-trader qdc daily-pipeline --batch-size 50
```

只跑采集，不导出 Qlib：

```powershell
conda run -n ai-trader qdc daily-pipeline --batch-size 50 --skip-export
```

指定 Qlib 导出起点：

```powershell
conda run -n ai-trader qdc daily-pipeline --batch-size 50 --export-start 2026-05-11 --market-name all_a
```

## 6. Windows 计划任务建议

先确认 `conda.exe` 路径：

```powershell
where conda
```

如果路径是 `D:\Miniconda3\Scripts\conda.exe`，可创建每日 18:30 任务：

```powershell
schtasks /Create /TN "QDC Daily Pipeline" /SC DAILY /ST 18:30 /TR "cmd /c cd /d E:\code\pit-ashare-event-lake && D:\Miniconda3\Scripts\conda.exe run -n ai-trader qdc daily-pipeline --batch-size 50 >> data\quant_data_center\logs\daily-pipeline.log 2>>&1"
```

查看任务：

```powershell
schtasks /Query /TN "QDC Daily Pipeline" /V /FO LIST
```

手动触发：

```powershell
schtasks /Run /TN "QDC Daily Pipeline"
```

删除任务：

```powershell
schtasks /Delete /TN "QDC Daily Pipeline" /F
```

## 7. 失败恢复

DuckDB 当前按单写进程使用。运行每日采集前建议关闭 `qdc console`，避免读连接影响写入。

如果任务中断，先恢复陈旧 running：

```powershell
conda run -n ai-trader qdc recover-running --older-than-minutes 60
```

重试失败任务：

```powershell
conda run -n ai-trader qdc run-backfill --retry-failed --limit-tasks 20
```

重新跑当天 pipeline：

```powershell
conda run -n ai-trader qdc daily-pipeline --date 2026-05-11 --batch-size 50
```

同一日期同一批标的的任务会按 `dataset/source/date/symbol_batch` 去重，重复规划不会生成重复任务。

## 8. 运行边界

当前第一版仍有这些边界：

```text
全市场 AkShare 免费源请求量较大，首次运行应先用 --plan-only 和小范围 smoke 验证。
news 只能作为近实时补位源，不适合作为完整历史新闻训练源；公告也只是标题级弱事件源。
adj_factor 当前由未复权和前复权日线推导，严格 PIT 复权后续仍需官方分红送配源。
price_limit 当前是规则推导，ST、新股首日、复牌首日等细则仍需增强。
daily-pipeline 默认导出截至当日的全部可用 daily_bar 到 Qlib provider，随着数据增长导出时间会变长。
```

## 9. 后续实施顺序

```text
P0：跑通 daily-pipeline 小范围真实 smoke。
P1：跑通 all_a 全市场单日真实采集，观察耗时、失败率和上游限流。
P2：根据真实耗时调整 batch-size、运行时间和是否拆分 news。
P3：增加覆盖报告，输出 daily_bar / adj_factor / price_limit 相对交易日和标的的覆盖率。
P4：接 CNINFO / 交易所公告源，保存 PDF、正文、hash 和准确披露时间。
P5：接授权历史新闻源，再重建 daily_news_factor。
P6：再补历史回补，把 Qlib provider 从“每日积累”扩展到完整训练期。
```
